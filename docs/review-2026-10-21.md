# 日志字节路径审查与优化（2026-10-21）

基于 `501b713` 审查 Matcher、Pattern/PatternList、LiteralScan、Responder、Session 写入/关闭与 Cleanup 的契约，并沿 net-connector 的传输和日志调用追踪到 Redactor。本轮确认的性能问题是：没有秘密规则时，过滤器仍创建等长 pending/hidden 字节窗口，再扫描、释放它们。

现在仅在规则为空、旧尾部已排空时直接交付独立二进制字符串。规则删除后尚未排空的旧掩码仍走原路径；非空明文分隔隐藏区间，空分片不改变连续性；被抑制的字节不输出。该优化没有改变 IO/PID 所有权、匹配优先级、期限或公开 API。

Ruby 4.0.6、macOS arm64，同一 `benchmark/redactor.rb` 比较起始库副本和候选库，3 个样本、每样本 5 次操作，以下为中位数。输入 65536 字节；stream 每块 4096 字节，计时包含新建过滤器与拼接输出。

| 场景 | 原耗时 ms | 新耗时 ms | 原分配对象 | 新分配对象 |
| --- | ---: | ---: | ---: | ---: |
| empty_rules | 0.125 | 0.036 | 86 | 56 |
| empty_rules_stream | 0.207 | 0.051 | 611 | 131 |
| empty_rules_suppressed | 0.127 | 0.013 | 81 | 51 |

有规则路径没有预期的性能改进；例如 stream_4096 的分配仍为 2656，update_pending 仍为 161。短样本耗时存在噪声，不据此声称有规则路径加速或网络吞吐提高。Ruby 字符串可共享底层存储，独立返回值并不意味着立即复制全部字节。

复测：`bundle exec ruby benchmark/redactor.rb --samples 3 --iterations 5`；添加 `--library /path/to/baseline/lib` 可使用独立基线。输出 JSON 包含源码摘要及样本。新场景也参加 `script/ci` 的 smoke 验证。

既有二进制分片、规则变更、旧掩码保留及抑制输出测试继续适用；新增调用方可变输入、独立返回值和重新启用规则的组合检查。另外以旧实现为对照执行固定种子 20261021 的 100000 次 append/suppress/规则更新/finish 操作，结果逐次一致。此差分实验用于审计，不替代语义测试或实机验证。

最终本地 `bash script/ci` 通过：634 runs、11779 assertions，无失败/错误/跳过；104 文件 lint、API/RBS、示例、基准及普通/Bundler 隔离安装通过。与 net-connector 候选包共同安装后，安装文件与候选制品逐字节一致，连接器 PTY smoke 通过。当前证据为 macOS/Ruby 4.0.6，未执行远程 CI、完整操作系统矩阵或发布。
