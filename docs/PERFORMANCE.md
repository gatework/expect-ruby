## 0.7.0 测量边界

本轮删除重复门面、全局配置和外部终端辅助进程，主要收益是缩小维护与故障处理边界；没有据此宣称吞吐提升。


## 工作负载与边界

| 脚本      | 范围                                                                                                                                         |
|-----------|----------------------------------------------------------------------------------------------------------------------------------------------|
| matching  | 4 KiB、64 KiB、1 MiB 静态扫描；多模式/来源/组；UTF-8 捕获；同时就绪的真实管道；1/4/16 MiB 持续读取至 EOF |
| relay     | 无转义、字面转义、16 个正则转义、长字面前缀未命中；1/4/16 MiB 已缓冲转接；正常与短写目标；1/16/64 个真实管道全部就绪或仅末个来源就绪 |
| send_slow | 真实本地 socket；无回显、持续回显；零延迟和每字符 1ms 延迟                                                                                   |
| scaling   | 多来源同时就绪、逐个 EOF 继续与顺序/尾部校验、阻塞目标下其他来源的推进                                                                       |
| redactor  | 空规则、无命中/稀疏/连续/高重叠；包含关系、多秘密、二进制、原文替换标记、分块、长短秘密混合分片、partial finish、规则更新、无候选与密集候选长尾 |

`matching` 的扫描用内部 `find_match` 单独度量缓冲扫描，排除 PTY 启动和回调开销；就绪场景包含管道写入、选择和读取。`relay`
的转义与混合目标场景均运行完整转接循环，包含扫描、排队和交付。短写模拟目标吞吐受限，不等同于真实慢网络。`send_slow` 包含
socket、接收线程和完整回显校验的成本；无回显时计时止于接收方收齐数据。

处理字节数表示每轮提供给场景的输入字节数（混合目标为两份交付量），不是正则引擎实际访问内存的次数。分配量是整个 Ruby
进程的计数，socket 场景包含接收线程的分配。基准不提供 CPU 或网络隔离；耗时波动不能直接归因于代码变化。

`matching` 还比较同一次等待中持续追加 32 个 1 KiB 块后的字面与正则扫描；该场景每块都检查未命中，最后验证完整偏移，相关检查包含在计时内。初始窗口分别为
64 KiB 和 1 MiB，均使用 32 个模式。

`growing/*` 从真实管道以 16 KiB 块持续写入，通过公开 `expect` 等待一个始终未命中的字面模式及 EOF，验证全部输入保留。
计时包含管道与发送线程创建、完整读取和资源关闭；默认每个样本只执行一次，smoke 缩小到 64 KiB。

`relay` 的 `prebuffered/*` 在公开 buffer 中放入 1/4/16 MiB，再运行完整转接与 EOF 派发；没有转义规则，排除正则扫描开销。
默认每个样本执行一次，smoke 使用 64 KiB；校验全量交付、缓冲排空且无待写游标，不能以丢弃尾部换取加速。

`relay` 的 `escape/literal-prefix-miss` 通过真实 `Expect.interconnect` 处理 65,536 个 `a` 和末尾 `?`，同时注册
65,536 个 `a` 加 `!` 的字面转义规则。来源保持打开，零超时的连续调用会把所有未匹配输入交付并校验完整输出；因此会实际经过潜在前缀扫描。

`scaling` 默认使用 1、16、64 个真实管道来源，等待并消费所有同时就绪的标记，然后验证已知 EOF
的逐源继续；另一场景把目标管道填满且不消费，验证其他来源仍可触发退出转义。`scaling` 和 `relay` 均支持 `--sessions N`
单独选择容量，运行前检查进程描述符上限。`--smoke` 仅使用 1、8 个来源。
`all_ready` / `all_eof` 复用同一冻结声明；`declare_and_ready` / `declare_and_eof` 每次通过公开 `Expect.expect` 重新声明，计入编译成本。

每个样本记录计时区间前后的 RSS 和打开描述符数，以及进程的描述符上限；采样自身不进入计时或分配计数。RSS 是端点快照，受 Ruby
堆和分配器保留影响，不代表峰值或存活对象大小。平台不支持某项采样时记录 `null`。描述符快照也不是长期泄漏证明，应同时检查重复样本和关闭流程。

`redactor` 每次操作创建独立过滤器，分块数据在计时前准备，计时包含过滤器构造、append 和两次 finish。
主要输入规模为 64 KiB，高重叠秘密长度为 1/32/1024/4096 字节；smoke 缩小为 512 字节及 1/32/128 字节秘密。
长尾两项使用 4096 字节重复前缀，默认每样本 100 次；smoke 缩小为 32 字节和 1 次。其他过滤负载仍默认 5 次，`--iterations`
可统一覆盖。
`mixed_lengths_stream_*` 同时注册 5 字节短秘密与一个不命中的 4096 字节长秘密，对 8195 字节连续短秘密以 1/64/4096
字节分块过滤；默认每样本一次，smoke 改用 128 字节长秘密及 85 字节输入，结果必须只有一个替换标记。
公共 Runner 会加载完整 Expect（含 PTY）；基准本身不启动 PTY 会话，独立 `require "expect/redactor"` 的无 PTY 契约由测试验证。
